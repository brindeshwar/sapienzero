## Protection of `main`

Applied with `PUT /repos/{repo}/branches/main/protection`, read back, and tested with a real push.

- Pull request required (0 approvals, because a solo owner cannot approve their own pull request; the checks are the gate)
- Required status checks: `ci-ok` and `docs`; branch must be up to date before merging
- Linear history; conversation resolution required
- Force pushes and deletion blocked; **applies to administrators too** (no bypass)
- Test result: a direct `git push` to `main` was rejected with "protected branch hook declined"

## Protection of release tags

A tag ruleset named "protect release tags" for `refs/tags/v*`: deletion, update and non-fast-forward are blocked.

## Rebuilding

Re-run the same API calls, or re-enter the values above in the GitHub settings pages. The names `ci-ok` and `docs` must match
the job names in `.github/workflows/`; renaming a job requires updating the protection in the same change.
